## Что проверяется и как влияет на решение

| Проверка | Правило текущей программы |
| --- | --- |
| Доверенные источники | `ozon.ru`, `wildberries.ru`, `market.yandex.ru`, `vseinstrumenti.ru`, `citilink.ru`, `xcom-shop.ru`, `komus.ru`: зелёный статус сразу, остальные риски не вычисляются. Только точный домен после удаления `www.` |
| Коммерческий сайт | Подтверждённый профильный сайт с товаром и контактами — положительный признак. LIVE использует ограниченную эвристику успешного чтения страницы |
| Возраст домена | От 3 лет — положительный признак; от 1 до 3 лет и менее 1 года — предупреждения. Молодой домен сам по себе не означает мошенничество |
| История сайта | Подтверждённая стабильная тематика — положительный признак; резкая смена — сильный риск. Нет архива или тематика не изучена — непроверенность |
| ИНН и текущая компания | Нет ИНН — предупреждение; компания действует — положительный признак; текущая компания не действует — сильный риск. Неизвестный статус не равен ликвидации |
| Согласованность реквизитов | Согласованные реквизиты — положительный признак. Несколько ИНН при установленном актуальном продавце могут быть историей; без установленного продавца — неполнота |
| Несколько получателей оплаты | Необъяснённая одновременная оплата разным юрлицам — сильный риск |
| Возраст компании/ИП | Флаг недавней регистрации — предупреждение и ручная проверка. Числовой порог давности в программе не задан; возраст домена его не заменяет |
| Госзакупки | Подтверждённое участие — положительный признак; отсутствие сведений не является отдельным риском |
| Смена руководителя | Менее 6 месяцев — предупреждение. В evidence называется `red_flag`, но само по себе не даёт красный итоговый статус |
| Компания не совпадает с реквизитами сайта | Достаточно для красного статуса у недоверенного домена; исторические ИНН сначала отделяются |
| КАД: банкротство | Любое подтверждённое банкротное дело — красный у недоверенного домена |
| КАД: ответчик | Дела ответчика — предупреждение. Повышенный риск: минимум 3 дела ответчика и минимум 2 дела за последние 730 дней. Свежие дела считаются во всех ролях, а не только ответчика |
| КАД: истец/прочие роли | Без доказанного негативного контекста — информационный признак, не автоматическое обвинение в мошенничестве |
| Недоступные сервисы | Сохраняются как непроверенность. Недоступный КАД, WHOIS, CMS или IP не всегда блокирует зелёный статус |
| CMS и IP | Справочная информация; CMS и общий IP сами по себе не определяют надёжность. Количество соседних сайтов не определяется |
| Получатель счёта | Отдельная функция сравнивает ИНН со счётом строго по строке; другой или отсутствующий ИНН — «НЕ ОПЛАЧИВАТЬ». Название функция не сравнивает; LIVE её автоматически не вызывает |

## Четыре статуса и порядок решения

1. Доверенный домен → **✅ ПОСТАВЩИК ПРОШЁЛ ПРОВЕРКУ**, без остальных проверок.
2. Остальные: банкротство → **🔴 ПРИЗНАКИ ВЫСОКОГО РИСКА — НЕ ОПЛАЧИВАТЬ**.
3. Другой сильный риск + минимум две записи риска → красный.
   Несовпадение компании и реквизитов сайта достаточно само по себе.
   Один сильный риск без второй записи обычно не даёт красный.
4. Нет положительных признаков, есть непроверенные данные → **⚪ НЕДОСТАТОЧНО ДАННЫХ**.
5. Иначе любой риск → **🟡 ТРЕБУЕТСЯ РУЧНАЯ ПРОВЕРКА ПЕРЕД ОПЛАТОЙ**.
6. Без рисков: ИНН + действующая текущая компания + согласованные реквизиты
   или установленный актуальный продавец + домен от 3 лет или подтверждённая
   стабильная тематика → зелёный. Непроверенный КАД может оставаться.
7. Если этой комбинации нет и есть непроверенные данные: жёлтый при ИНН и
   действующей компании; иначе белый. В остальных случаях — белый.

Условия пункта 6 группируются так:
`ИНН AND действует AND (реквизиты согласованы OR продавец установлен) AND
(домен >= 3 лет OR тематика стабильна)`.

## Реальная автоматизация

Основной `verify_live_supplier()` по умолчанию читает до **3 страниц** продавца,
проверяет домен после переходов, извлекает реквизиты и контакты, получает
RDAP/WHOIS и список снимков Wayback.

Автоматически **не подтверждаются** действующий статус юрлица, смена руководителя,
участие в закупках, арбитраж, прежняя тематика сайта и получатель счёта.
CMS/DNS доступны отдельными функциями, но в этом LIVE-потоке не вызываются.
Штатного адаптера КАД нет: без явно переданного fetcher результат ручной.
Связанные физические лица автоматически не проверены.

Отдельный глубокий контроль использует заранее внесённые сведения о конкретных
компаниях. Его нельзя считать универсальным автоматическим сбором реестра.

## Закупочный отбор

В EXACT_MODEL antifraud идёт после модели, товарных цен и предварительной
экономики. Запас по умолчанию — **18%**, предел требуемой скидки для кандидата
на запрос цены — **20%**. Комиссия ЕАТ приоритетна; fallback — настройка 3%.
Это предварительный отбор, неизвестные расходы остаются неизвестными.

Новый TOP-3 исключает красных и проверяет следующих; жёлтые и белые допускаются
с сохранением статусов. Подтверждённое наличие/заказ имеют приоритет,
неизвестное наличие — резерв. Старый `select_quotes()` допускает только зелёных
с точной моделью, доступной карточкой и ценой не выше заданного порога.
Публичная цена не становится подтверждённой закупочной ценой.

Самостоятельная проверка навыком не требует тендера или экономического допуска.
Изменение каталога навыка не изменяет правила исполняемого Python автоматически.

## Как использовать и изменять

- `$supplier-check Проверь поставщика: ИНН …, сайт …`
- `$supplier-check Проверь поставщика по этим реквизитам и счёту …`
- `$supplier-check Добавь в навык правило: …`
- `$supplier-check Измени правило SUP-… в программе и навыке: …`

Каталог и инструкции можно редактировать напрямую. Неутверждённые предложения
хранятся как `CORE_RULE_CANDIDATE`. При изменении runtime нужен профильный
regression-тест и синхронизация каталога; runtime остаётся без зависимости от LLM.
