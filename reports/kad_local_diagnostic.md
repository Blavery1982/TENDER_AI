# Локальная диагностика КАД на Mac

Запустить в Терминале Mac один раз:

```bash
cd /Users/lubov/Documents/TENDER_AI && .venv/bin/python -m suppliers.kad_diagnostic 5904993922
```

`5904993922` — контрольный ИНН предыдущего исследования, а не свежая проверка
актуального продавца. Для своего поставщика замените его ИНН, однозначно
установленным по текущим реквизитам/оферте/счёту.

Открывается видимый Chromium из существующего Playwright-окружения проекта.
Скрипт вызывает браузерный сборщик `KADClient._browser_pages()` и его штатные
парсеры. Один поиск по ИНН, одна страница выдачи, максимум одна карточка.
Прямой HTTP, fallback, повторные поиски, CAPTCHA-обход и Google Sheets не запускаются.
При блокировке/challenge проверка прекращается, браузер закрывается.
При timeout сохраняется незавершённый этап, автоматического повтора нет.

Новый каталог каждого запуска:
`data/kad_diagnostics/<ИНН>/<дата-время-UTC>/`.
Путь выводится в начале команды и в последней строке журнала.

- `stages.jsonl`: последовательность этапов с датами, HTTP-кодами, признаками
  challenge, проверкой значения поля, нажатием кнопки и реальной отправкой POST.
  Cookie, заголовки сессии и полные HTML-страницы не сохраняются.
- `summary.json`: итог всех этапов и результат штатного `check_kad()`.
- `sample_case.json`: извлечённые поля первой карточки, ссылка, роль нашего ИНН,
  происхождение полей и текст публичной карточки без скриптов/HTML (до 30 000 знаков).
  Создаётся, только если карточку удалось прочитать.
- `client_result/`: локальная запись результата штатного клиента; рабочий
  production-кэш не переиспользуется и не меняется.

В `summary.json`:

| Поле | Что подтверждает |
| --- | --- |
| `site_reached`, `site_opened`, `site_http_status` | Ответ сайта отдельно от успешного открытия; 451 не является успешным открытием |
| `challenge_detected`, `access_blocked` | Маркеры штатного детектора защиты отдельно от HTTP-блокировки |
| `inn_filled` | Введённое значение поля совпало с ИНН до Tab |
| `search_clicked` | Нажата кнопка «Найти» |
| `search_sent`, `search_inn_matches` | Наблюдался реальный POST `/Kad/SearchInstances`; в `Sides[].Name` передан наш ИНН |
| `results_appeared`, `results_count_confirmed`, `cases_found` | Наличие строк отдельно от подтверждённого счётчика; 0 отличается от неизвестного количества |
| `card_opened`, `card_http_status` | Навигация на первую карточку |
| `card_fields_extracted`, `role_matches_target_inn` | Реально полученные поля и роль по точному ИНН в обозначенной группе участников |
| `failure` | Тип/причина ошибки и последний этап перед ней |
| `diagnostic_success` | Подтверждён поиск нашего ИНН и проверена роль на одной карточке; при 0 дел роль неприменима |
| `kad_check.checked_in_kad`, `kad_check.complete` | Полнота проверки всего поставщика, отдельно от успеха диагностики |

`null` — этап не выполнен или не подтверждён. Если найдено более одного дела,
успешная диагностика одной карточки всё равно сохраняет `KAD_INCOMPLETE`:
остальные карточки автоматически не открываются.
Роль не выводится из самого факта нахождения дела. Если в карточке ИНН находится
только в тексте решения или у другого участника, сопоставление не подтверждено.

Код завершения 0 — диагностический сценарий подтверждён; 2 — не подтверждён.
Результат не является полной проверкой компании или самостоятельным antifraud-допуском.

В итоговом antifraud для установленного продавца технически непроверенный КАД
сохраняет YELLOW/ручную проверку, даже при прочих положительных сигналах и
доверенном домене. Комментарий теперь показывает причины КАД из warnings/errors,
включая 451, CAPTCHA/challenge и timeout. Подтверждённый высокий риск других проверок сохраняет RED. Production-КАД теперь
считает только дела ответчика, без банкротства, свежести и прежних порогов 3/2/730;
подробности — kad_minimal_production.md. Подробная диагностика не является
production-проверкой и сохраняет свой отдельный формат разработки.

Из Codex после прежнего HTTP 451 новые LIVE-запросы не выполнялись.
Локальный LIVE-результат пока не подтверждён; профильные тесты используют mock.
