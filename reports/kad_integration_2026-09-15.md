## Реализовано

- `suppliers/kad_client.py`: HTTP-поиск, один Playwright fallback при техническом
  сбое/непонятном ответе; карточки и пагинация, без обхода защиты.
- CAPTCHA/challenge/HTTP 403, 429 или 451 → `KAD_REQUIRES_MANUAL_CHECK`, без
  переключения транспорта или автоматического повтора этого поставщика.
- `suppliers/site_requisites.py`: актуальный продавец по текущим юридическим
  страницам; один ИНН в карточке товара недостаточен. Несколько ИНН без
  однозначного текущего продавца → YELLOW, запрос КАД не выполняется.
- Старые ИНН из Wayback автоматически не проверяются. Сложная история смены
  юрлица требует отдельного разбора конкретного расхождения.
- `suppliers/arbitration.py::check_kad()` по умолчанию подключён к сборщику,
  сохраняет номера, ссылки, роли, доступные статусы и решения, полноту проверки.
  Неполные результаты не превращаются в «дел нет»; ссылки остаются для ручной проверки.
- Роль проверяется по нашему ИНН внутри группы участников. ИНН другой компании
  или упоминание ИНН в тексте решения не означает роль проверяемого поставщика.
- `suppliers/verification.py`: неизвестный поставщик без полного КАД по текущему
  ИНН не получает GREEN. Явно неоднозначный продавец — YELLOW.
  Подтверждённое банкротство текущего ИНН — RED, включая частичный результат
  и доверенный домен. Другие подтверждённые красные признаки текущего продавца
  не понижаются только из-за недоступности КАД.
- Пороги сохранены: минимум 3 дела ответчика и минимум 2 свежих дела за 730 дней.
  Свежие дела по исходной логике считаются во всех ролях.
- `suppliers/live_verification.py`: текущий продавец → адаптер компании → КАД →
  RDAP/WHOIS, Wayback CDX → итоговый antifraud. Общий вызов подключает обе
  существующие LIVE-ветки без изменения их оркестрации.

## Полнота данных и ограничения

Парсер поддерживает HTML-ответ с явным общим счётчиком и прямыми ссылками
`/Card/<UUID>`, затем читает карточки отдельно. Для успешного результата нужны
полное совпадение количества дел и подтверждённые ИНН, роль, дата и признак
банкротства/категория по каждому делу. Непонятная или изменившаяся разметка
возвращает `KAD_INCOMPLETE`, а не фиктивный успех. Статус/решение при отсутствии
явного поля остаются пустыми; анализ судебных PDF в эту интеграцию не включён.

## Кэш

Ключ: ИНН + дата/время. Запись сохраняется в
`data/cache/kad/<ИНН>/<дата-время>.json`, связь с текущими реквизитами — в
`data/suppliers/_kad/<хэш-домена>/<дата-время>.json`. Каталоги исключены из Git.
Cookies, логины, пароли и авторизованные сессии не сохраняются.

Без заданного срока кэш, включая блокировки, повторно используется только
в рамках текущего запуска. Между запусками можно использовать только успешный
результат в пределах переданного `cache_max_age_hours`. Исходная дата получения
сохраняется; кэш повторно оценивается текущими правилами без сетевого запроса.

**Предложение: 24 часа между запусками. Пользователь пока не утвердил срок;
значение по умолчанию остаётся `null`.** `--force-refresh` — явная повторная
проверка, а не автоматическая попытка после CAPTCHA/ограничения доступа.

Самостоятельная проверка установленного текущего ИНН:

```bash
.venv/bin/python -m suppliers.kad_client <ИНН>
```

Сборщик сохраняет локальный результат запросов, включая недоступность.
Для межзапускового кэша параметр `--cache-max-age-hours` задаётся по согласованному
пользователем сроку. Сейчас реальные обращения повторять после 451 не следует.
