# Исправление бизнес-порядка TENDER_AI — 15.09.2026

## Изменено

Раньше загрузка карточки сразу скачивала документы, анализ условий контракта
предшествовал поиску цены, а supplier flow использовал порог с вычетом комиссии
и мог проверять поставщика при одном предложении.

Основной обработчик теперь `pipeline.single_purchase_test.run_check`.
`pipeline.mvp_exact_batch.run` использует тот же обработчик для каждой закупки.

## Новый маршрут

```text
Карточка ЕАТ → действующие фильтры → GOODS
  → точная модель в карточке?
      да: без загрузки документов → выбранная модель
      нет: нужные документы → точная модель в них?
          да: выбранная модель, без подбора аналогов
          нет: явные характеристики заказчика → проверка моделей
               → самая дешёвая подтверждённая полностью подходящая модель
  → ограниченный поиск цен именно выбранной модели
  → две цены разных продавцов на нужное количество ≤ НМЦК × 0,82?
      нет: NO_ECONOMIC_SIGNAL → следующая закупка
      да: TOP-3 минимальных подтверждённых цен
           → проверки только выбранных поставщиков / antifraud / КАД
           → условия контракта → дополнительные расходы
           → каноническая финальная экономика → бизнес-решение
           → локальное сохранение → Google Sheets
```

Первичный поиск по умолчанию ограничен 40 кандидатами; при двух ценах ниже
порога продолжается до общего лимита 100. Минимум относится к проверенным
источникам. При нехватке третьего КП или неизвестной стоимости специальных
обязанностей финальное решение требует ручной проверки.

Полное коммерческое обозначение сохраняется при проверке страницы продавца.
`Bergauf Other PLUS 25 л` не подтверждает `Bergauf Keramik PLUS 25 кг`.
Разные подтверждённые продавцы одного marketplace считаются разными
поставщиками; неопределённый продавец не считается отдельным подтверждённым КП.
Полные стоимости КП не умножаются на количество повторно и сравниваются
с ценами единицы по стоимости необходимого количества.

Старая экономика batch checkpoint не используется. Финальный расчёт общей
цепочки заново собирается из текущих количества, выбранной модели, выбранных
КП и расходов. Изменение модели исключает КП прежней модели. Ошибка Sheets
сохраняется как EXPORT_ERROR и не повторяет исследование; CLI показывает путь
к локальному результату. Локальные ошибки закупок не останавливают batch;
BrowserAuthError пробрасывается как системная потеря авторизации. Ошибки
общего сбора/открытия авторизованной сессии остаются вне локального skip.

## Файлы

- `pipeline/single_purchase_test.py` — общий порядок, отложенная загрузка,
  фиксация выбранной модели, контракт после поставщиков, локальный результат
  перед экспортом.
- `pipeline/mvp_exact_batch.py` — вызов общего обработчика, отказ от устаревшей
  экономики checkpoint, передача рассчитанных данных в production payload.
- `eat/single_purchase.py` — отдельная загрузка карточки и нужных документов,
  сохранение прежнего архива, обнаружение подтверждённой потери авторизации.
- `documents/pipeline.py` — возможность извлечь источники без анализа условий
  контракта; действующие правила специальных обязанностей и отрицаний сохранены.
- `model_search/live_price_search.py`, `model_search/product_evidence.py` —
  проверка полной товарной идентичности и подтверждённого продавца Маркета.
- `model_search/playwright_provider.py` — ограничение первичного поиска без
  двух хороших цен и продолжение глубокого поиска при сигнале.
- `suppliers/exact_model_flow.py`, `suppliers/price_search_flow.py` — gate без
  комиссии, TOP-3 до antifraud, только выбранные продавцы, общая идентичность
  поставщика и сравнение полных стоимостей КП.
- `calculator/result_decision.py`, `calculator/business_decision.py` — текущие
  входы финальной экономики и различение продавцов marketplace; финансовая
  формула не изменена.
- `main.py` — вывод локального результата и код ошибки при сбое экспорта.
- `tests/test_business_order.py` — новые проверки порядка и остановок.
- `tests/test_exact_model_branch.py`, `tests/test_single_purchase_test.py`,
  `tests/test_single_purchase_archive.py` — корректировка прежних ожиданий и
  проверка отсутствия скачивания в режиме карточки.
- `docs/TENDER_AI_MASTER_SPEC.md`, `README.md`, `AGENTS.md` — фиксация согласованного
  порядка. Этот отчёт — `reports/business_order_2026-09-15.md`.

## Не трогал

Не менялись бизнес-фильтры ЕАТ, география, категории, правила подсчёта КАД,
финансовая формула, approved_rules, credentials и существующие рабочие данные.
AI/LLM и новые облачные парсеры не добавлялись. Диагностические legacy-команды
не превращались в новые основные runner. Контроль одной закупки сохраняет
существующий диагностический просмотр фильтра; batch останавливается при
отклонении полной карточки действующими фильтрами.
