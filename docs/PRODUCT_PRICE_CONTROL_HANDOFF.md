# Проверка на другом компьютере

Цель: проверить новый контрольный режим Codex CLI → Yandex Search API → HTTP/Playwright →
карточки продавцов на пяти заранее известных товарах. Это не полный просчёт
тендера: пример содержит только названия, без ТЗ, расчёта экономики и Sheets.
Пустой `documents` не подтверждает соответствие реальным требованиям тендера.

## Подготовка

1. Получить актуальную `main` из https://github.com/Blavery1982/TENDER_AI.
   Существующие незакоммиченные изменения не затирать; при необходимости
   использовать отдельную копию репозитория.
2. Прочитать `AGENTS.md` и `docs/TENDER_AI_MASTER_SPEC.md`.
3. Нужны Python 3.11+, Codex CLI в PATH и выполненный вход пользователя
   через его подписку. Проверить `codex --version` и `codex login status`.
   Если входа нет, попросить пользователя выполнить штатный `codex login`.
   Не копировать `auth.json`, cookies или ключи между пользователями.
4. Кандидат для теста — `gpt-5.6-luna`. Если модель недоступна или CLI
   не поддерживает параметры, сохранить точную причину; не подменять модель
   другой и не переключать авторизацию на платный API автоматически.

Для этого режима `.env`, Service Account и отдельный ключ OpenAI не нужны.
Нужны folder_id и API-ключ Yandex Search API в macOS Keychain. Текущий backend
credentials поддерживает только macOS; Windows/Linux завершаются до Codex и браузера
с `SEARCH_API_NOT_CONFIGURED`. Ключи не передавать в чат, Git или отчёты.
На macOS проверить `.venv/bin/python -m security.yandex_credentials status`.
Если запись отсутствует, пользователь вводит folder_id и ключ через штатный
интерактивный `.venv/bin/python -m security.yandex_credentials setup` (ключ скрыт).

Windows PowerShell, из корня репозитория (существующую `.venv` не пересоздавать):

```powershell
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt
.venv/Scripts/python -m playwright install chromium
```

На macOS/Linux использовать `python3 -m venv .venv` и `.venv/bin/python`.
Перед LIVE нужен рабочий графический сеанс: контроль открывает видимый Chromium.

## Проверки и один LIVE-проход

Запустить только профильные тесты, не полный suite:

```powershell
.venv/Scripts/python -X utf8 -m unittest tests.test_product_control_yandex tests.test_yandex_search.ProviderTests -v
```

Затем один запуск пяти товаров:

```powershell
.venv/Scripts/python -X utf8 main.py --product-price-control config/product_price_control.example.json
```

Запуск расходует лимит Codex пользователя. Не проверять счётчик лимита в
интерфейсе и не изменять настройки аккаунта. Не запускать дополнительно
массовый сбор, `--single-purchase-test` или запись в рабочую Google Sheets.

Yandex Search API: максимум 30 платных запросов на весь запуск, включая подбор
модели и отложенные задания. Ошибка API останавливает дальнейшие запросы без
повторов и без перехода на браузерный поиск. HTTP-код сохраняется в диагностике
API; это не CAPTCHA магазина. В result.json есть api_calls и search_log.
Карточки магазинов читаются через HTTP с резервным Playwright. CAPTCHA/403/429
магазина сохраняются для ручной проверки. Временные сетевые ошибки карточек
повторяются после остальных товаров один раз; успешные результаты сохраняются.

## Что вернуть владельцу

Результаты — в новой папке `data/product_price_control/<run>/`:
`result.json`, `intake_*.json`, `prices_*.json` и сформированные Markdown-отчёты.
Они исключены из Git. Передавать владельцу только файлы этого контрольного
запуска; `.env`, секреты, сессии и чужие рабочие данные не прикладывать.

В ответе указать commit, ОС, версии Python/Codex, результат профильных тестов
и таблицу:

| Товар | Выбранная модель | Подходящих продавцов | Три цены и ссылки | Причина остановки |
|---|---|---:|---|---|

Для кабеля выбранное обозначение должно сохранять 13Р-Т3 и Gonsin;
`DIN 13` отдельно недопустим. Цены подтверждать карточками продавцов,
не сниппетами. Отличать все найденные цены от `eligible_offers`, где
подтверждены наличие и извлечённые обязательные параметры. Отсутствие
документов в примере не означает полного соответствия ТЗ.

Если тесты/запуск падают, сохранить тип ошибки и этап, остановиться и описать
причину. Не исправлять production-код или ослаблять проверки в ходе приёмки.

## Если позднее понадобится Google Sheets

Создать локальную `.env` из `.env.example`, только если её ещё нет, указать
`GOOGLE_SPREADSHEET_ID` и `GOOGLE_SERVICE_ACCOUNT_FILE`. Ключ Service Account
владелец передаёт безопасно отдельно; его аккаунту нужны права редактора таблицы.
Не хранить ключ в Git и не присылать его в чат. Для исправления строки 8 нужен
отдельный разрешённый запуск с записью; текущий контроль этого не делает.
