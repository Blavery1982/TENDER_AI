# TENDER_AI

Локальный проект на Python для будущей работы с тендерами.

## Структура проекта

- `app/` — основная логика приложения и его интерфейс.
- `eat/` — будущая работа с ЕАТ.
- `filters/` — правила отбора и фильтрации тендеров.
- `google_sheets/` — будущая интеграция с Google Таблицами.
- `suppliers/` — данные и логика работы с поставщиками.
- `calculator/` — расчёты стоимости и других показателей.
- `security/` — функции безопасной работы с данными.
- `reports/` — создание отчётов.
- `data/` — локальные рабочие данные.
- `data/tenders/<purchase_id>/` — единый архив одного тендера: исходные документы,
  `tender.json`, `document_extraction.json` и `brand_audit.json`.
- `logs/` — технические журналы работы программы.
- `config/` — настройки приложения без секретных данных.
- `tests/` — автоматические проверки программы.
- `main.py` — точка запуска программы.
- `requirements.txt` — список необходимых библиотек Python (пока пуст).
- `.env.example` — пример будущих переменных окружения без секретов.

Настоящие пароли, токены и ключи нельзя записывать в код. В будущем они будут храниться отдельно в локальном файле `.env`, который исключён из Git.

## Архив документов и проверка марок

Новая загрузка карточки через `eat.single_purchase` сохраняет все документы в отдельную папку
`data/tenders/<purchase_id>/`. Старая структура `data/contracts/` оставлена для совместимости.

Одноразовая миграция уже скачанных документов выполняется командой:

```bash
.venv/bin/python -m documents.migrate_tender_archive
```

Проверка локального архива на марки и товарные знаки:

```bash
.venv/bin/python main.py --audit-tender-archive
```

Результаты находятся в `data/tenders/_brand_lists/`:

- `brands_found.json` — подтверждённая марка найдена, с документом, страницей и фрагментом;
- `brands_not_found.json` — все документы прочитаны, совпадений нет;
- `review_required.json` — неполный архив, ошибка OCR или неоднозначный кандидат.
