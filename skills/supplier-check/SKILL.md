# Проверка поставщика

Общайся на русском. Прочитай [каталог правил](references/rules.json) и
[порядок применения](references/assessment.md) перед проверкой или изменением правил.
Каталог первоначально отражает код TENDER_AI на 15.09.2026. Значения порогов,
доверенные домены и точные тексты статусов хранятся в JSON.
Версия `2026-09-15.3` включает упрощённый КАД: только количество дел ответчика.
Прежний анализ банкротства, свежести, категорий и решений КАД отменён.

## Проверить одного поставщика

Достаточно сайта или ИНН; тендер, модель товара, НМЦК и Google Sheets не нужны.
По одному названию сначала установи конкретное юрлицо; если есть несколько
совпадений, покажи их и запроси ИНН либо сайт, продолжая доступную проверку.
Если дан только ИНН, проверяй компанию и КАД; проверки домена обозначай как
неприменимые до установления связи с конкретным сайтом.

Для актуальной проверки открывай публичные первоисточники: сайт продавца и его
оферту/реквизиты/оплату, сведения ФНС о конкретном ИНН, КАД, RDAP/WHOIS и
снимки Wayback. Поиск используй для нахождения ссылок, факты подтверждай по
открытой странице или документу. Дата регистрации домена не является датой
регистрации компании. Не переноси сведения другого одноимённого поставщика.
Наличие архивных снимков не доказывает прежнюю тематику сайта.

Сначала установи ИНН актуального продавца по текущим юридическим страницам.
При неоднозначности — жёлтый статус, поиск КАД не выполняй. Старые ИНН из Wayback
не проверяй автоматически: отдельная проверка оправдана конкретной сменой юрлица,
расхождением реквизитов или подозрительной историей, которую нужно показать.

Если проект доступен, для КАД используй детерминированный сборщик:
`.venv/bin/python -m suppliers.kad_client <актуальный_ИНН>`.
Он сохраняет результат локально. При `KAD_REQUIRES_MANUAL_CHECK` останови
проверку этого поставщика: не меняй браузер, адрес или транспорт для обхода
защиты и не используй `--force-refresh` как автоматическую попытку после challenge.
Любая техническая невозможность и неоднозначная роль — `KAD_REQUIRES_MANUAL_CHECK`
с YELLOW и явной причиной, не нулевой счётчик. Сохраняй только ИНН, дату,
технический статус, число дел ответчика, итоговый KAD-цвет и короткий reason.
Не открывай карточки/решения, не скачивай документы, не сохраняй номера, ссылки,
категории или списки дел для этой проверки. Любое N > 0 — YELLOW с просьбой
вручную проверить судебные иски и добросовестность; 0 сам по себе не предупреждение.
Подробный `kad_diagnostic` остаётся исключительно инструментом разработки.
Успешный LIVE-поиск и сопоставление роли в выдаче ещё требуют проверки:
диагностика 15.09.2026 получила HTTP 451. Не выдавай UNIT-fixtures за реальные дела.

По умолчанию кэш переиспользуется только внутри одного запуска. Срок между
запусками пока не утверждён; `--cache-max-age-hours` задаётся по указанию
пользователя. Кэш сохраняет исходную дату получения; повторная оценка правил
не становится новой LIVE-проверкой.

Применяй только принятые правила каталога к подтверждённым фактам;
`CORE_RULE_CANDIDATE` показывай отдельно без влияния на решение.
Недоступность, CAPTCHA и отсутствие
результатов поиска сохраняй как непроверенность; они не означают отсутствие
дел или действующий статус компании. Не обходи CAPTCHA. Старые отчёты и
заранее заданные сведения контрольных примеров не считай свежей LIVE-проверкой.
Для проверки только предоставленных материалов явно укажи этот режим и их даты.

Отчёт: поставщик/ИНН/сайт, дата и версия правил, статус, таблица
«Правило — результат — факт — источник», подтверждённые риски, непроверенные
пункты и действия перед оплатой. Факты отделяй от итогового решения.
Если зелёный статус получен только по доверенному домену, явно напиши это:
конкретный продавец маркетплейса и получатель счёта этим не подтверждены.
Выявленные противоречия не скрывай даже при таком статусе программы.

Счёт проверяй, если он предоставлен. Отдельно показывай совпадение ИНН
получателя с актуальным проверенным поставщиком. Отсутствующий счёт —
«счёт не предоставлен», а не установленное несовпадение.

Самостоятельная проверка не запускает закупочный pipeline и не требует
экономического допуска. Не записывай её в Google Sheets, не отправляй сообщения
и не выполняй действия аккаунта без соответствующего задания.

## Изменить или добавить правило

Пользователь может редактировать каталог или задавать изменение обычным текстом.
Сохраняй стабильные ID существующих правил. Для нового правила зафиксируй:
условие, необходимые подтверждения, влияние на решение, источник/обоснование,
статус принятия и статус реализации в программе. Обнови версию и дату каталога.
Если пользователь сам утвердил конкретное правило, пометь его как принятое
пользователем. Собственные предложения обозначай `CORE_RULE_CANDIDATE` и не
применяй их как утверждённые правила.

Изменение навыка само по себе не меняет runtime TENDER_AI. При запросе изменить
только навык обнови каталог и порядок применения; укажи, что код не изменён.
При запросе изменить программу и навык прочитай текущие профильные модули и
тесты, внеси минимальное детерминированное изменение и regression-тест,
синхронизируй каталог. Не добавляй runtime-зависимость от Codex, навыка или LLM.
`core_knowledge/approved_rules.json` самостоятельно не дополняй.

Основной проект: `/Users/lubov/Documents/TENDER_AI`. Если он доступен, проверь
актуальный код перед утверждением «программа сейчас использует»; каталог —
документируемая версия, а исполняемый Python остаётся источником runtime-поведения.
Если проект недоступен, автономная проверка по каталогу остаётся возможной,
но синхронизацию с программой не объявляй выполненной.

Для изменения правил достаточно профильных тестов (обычно 5–30).
Полный suite запускай только по прямому указанию пользователя.
Проверяй навык штатным `skill-creator/scripts/quick_validate.py`, если доступен,
а JSON — стандартным JSON-парсером. В результате сообщай изменённые правила,
файлы, проверки и наличие расхождения с runtime.

## Расположение

Поддерживаемая папка навыка: `skills/supplier-check` в TENDER_AI.
Личный навык `~/.codex/skills/supplier-check` ссылается на эту папку, поэтому
правки через любой из этих путей изменяют один каталог. Навык можно скопировать
целиком на другой компьютер: проверка по каталогу не требует запуска TENDER_AI.
